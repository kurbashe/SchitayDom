# Игровые испытания — выполнить в DayZ

Это план испытаний, а не список пройденных проверок. Нужны клиент DayZ и тестовый dedicated ChernarusPlus; для групп — два клиента с разными идентичностями. Сервер загружает `-mod=@GorillaMap -serverMod=@GorillaMapServer`, клиенты — только `-mod=@GorillaMap`.

1. Зафиксировать версию игры, хеши обоих PBO, параметры запуска и список модов. Заменить старую монолитную сборку 0.1.0. Начать без других модов. Убедиться в отсутствии первой ошибки компиляции в клиентском/серверном RPT и script log. У клиента не должно быть серверного PBO; у сервера должны быть оба. При отсутствии серверного пакета клиент не должен подтверждать сохранение метки.
2. Открыть F6, закрыть Esc и кнопкой. Должны быть видны тёмная панель «Список меток», категории и кнопка создания; штатные индикаторы здоровья/предметов и quickbar должны скрыться. В клиентском script log проверить `OPEN: menu=GMapMenu sidebar=true priority=100`, затем `SNAPSHOT: ready=true`. Отдельно убедиться, что M другой карты не используется для этого теста. Повторить десять раз; управление персонажем и курсор должны восстанавливаться. Проверить смерть/потерю сознания/переподключение при открытой карте.
3. Проверить интерфейс в 1280×720, 1920×1080, 2560×1440 и ультрашироком формате. Панель не должна перекрывать модальные кнопки; длинные названия и список из 80 меток должны прокручиваться. Проверить русский шрифт и скруглённые PAA в игре.
4. Переназначить клавишу открытия. Проверить перенос, колесо, центрирование, координаты известных точек Черно/Электро, края 0/15360, Ctrl+C и линейку на двух точках с известной дистанцией.
5. Создать личную метку двойным щелчком, изменить цвет, значок, название и координаты; скрыть/показать; удалить с подтверждением. Ввод пустого названия, букв вместо координат и выхода за 15360 должен отклоняться. При полном лимите сервер должен отказать без изменения состояния.
6. Перезапустить сервер и клиент. Сохранённые личные метки и скрытие/настройки интерфейса должны восстановиться; другой игрок не должен получить чужие личные метки.
7. Загрузить демонстрационный Config. Круги радиуса 350 и 250 м должны масштабироваться вместе с картой. Попытка изменить серверную метку клиентским RPC должна отклоняться. Убедиться, что круги не выдают себя за действующую игровую радиацию/запрет строительства.
8. Создать группу A, пригласить B по имени; принять, создать общую метку. Она появляется у второго игрока не позднее следующего обновления. Личная метка A у B не отображается.
9. Участник B не изменяет чужую общую метку; автор и лидер могут. Проверить отказ при обращении к чужому `Id`, подмене признака `shared`, отправке неизвестной команды, недопустимого значка, испорченного протокола и спаме.
10. Отклонить приглашение, дать ему истечь, перезапустить сервер до принятия. Просроченное/несохранённое приглашение не даёт вступить. Проверить лимит группы и выход рядового участника. Выход лидера только после подтверждения распускает группу и удаляет общие метки.
11. На копии профиля повредить JSON и запретить запись в каталог профиля. Сервис должен сообщить ошибку, не заменять состояние пустым и не подтверждать успешное изменение. Проверить восстановление через валидный backup/pending при остановленном сервере.
12. Повторить проверки на финальном PBO без `-filePatching`, со своей действующей подписью и `verifySignatures=2`. Затем проверить взаимодействие с реальным набором серверных модов.

Для протокола результата сохранять: действие, ожидаемое/фактическое поведение, клиентский и серверный лог, версию игры и SHA-256 проверенного PBO. Отдельно отмечать **упаковку**, **компиляцию** и **игровой результат**.
