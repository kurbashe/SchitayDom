# Разделение клиента и сервера

```text
Игрок                         Dedicated-сервер
-mod=@GorillaMap               -mod=@GorillaMap
                              -serverMod=@GorillaMapServer

Интерфейс и снимок      RPC    Проверка прав, группы,
                   <------->  состояние, JSON
```

`gorillamap.pbo` — общий сетевой контракт и клиентский интерфейс. Серверу нужен тот же контракт для формирования ответов. `gorillamap_server.pbo` — отдельный серверный аддон: зависит от `GorillaMap` через `CfgPatches.requiredAddons[]`. Обратной зависимости нет. Он не объявляет новые физические сущности, которые клиент обязан был бы знать.

| Слой | Общий/клиентский пакет | Серверный пакет |
|---|---|---|
| `3_Game` | Протокол, категории, Marker/Peer/Snapshot, транспорт клиента | Конфиг, аккаунты, группы, хранилище |
| `4_World` | Приём только ответов | Сервис и приём запросов |
| `5_Mission` | MissionGameplay, меню, локальные настройки | MissionServer: запуск/остановка сервиса |

Общий пакет не содержит `GMapService`, классов серверного хранилища и `modded class MissionServer`. Серверный пакет не содержит GUI, текстуры и клавиши.

Клиент отправляет намерение. Серверный обработчик получает настоящую `PlayerIdentity sender`, проверяет протокол, лимиты, владельца, группу и координаты. После сохранения сервер отвечает только отправителю; клиент показывает снимок. Обработчики `DayZGame.Event_OnRPC` проверяют сторону, `target` и собственный ID **до чтения буфера**.

Сервер автоматически создаёт только каталог профиля и JSON. Клиент создаёт только локальный файл настроек интерфейса. Ни одна сторона не создаёт PBO другой стороны и не устанавливает моды другим компьютерам.

При обновлении с 0.1.0 замените прежний монолитный PBO новым общим и добавьте серверный пакет в `-serverMod`. Старый PBO нельзя оставлять под другим именем: определения классов задублируются. JSON Version=1 и RPC Version=1 сохранены; состояние удалять не нужно.
